# SDK parent reproduction recipe (source proposal)

This own-source adapter prepares two fresh GitHub-hosted Windows jobs, fresh-a and fresh-b. It derives six SDK parents with the original NeoForge 21.1.241 profile processor mains, ordered classpaths and ordered program arguments, and checks the official universal JAR as the seventh raw target. It does not install or start Minecraft. No hosted build or publication has been performed by this source preparation.

The intended checkout is a separately reviewed **own-only sparse checkout** of `tools/sdk-reproduction` in the public Motiquies repository. No private checkout, existing SDK, cache restore, uploaded binary input, user world, Mechanomania content or shader source belongs there. Actions use read-only repository permissions and do not persist checkout credentials. Child processors receive a small Windows environment allowlist, including none of the Actions service credentials. Standard ephemeral Actions service credentials used by checkout/upload are distinct from private/personal secrets.

`bootstrap.ps1` and its own `bootstrap_paths.ps1` function check the actual observed Windows image, system curl and hosted Python hashes before invoking Python. An updated image/tool fails closed; a separate facts review is needed. `hosted_worker.py plan` only validates own source/recipe locks and prints counts. `run` additionally requires a manual workflow dispatch bound to the explicitly reviewed commit and a new immediate RUNNER_TEMP directory. The public workflow is installed separately after review; a manual dispatch must bind its exact reviewed commit. Source publication does not claim a successful build.

The official Temurin 21.0.10+7 ZIP must match SHA256 08cae782814f027f8b159d6b68823f0f87422eb475c1a0ea1abc7a4357aaf11f, its complete 490-file tree must match 46fcbe366509bba6342e3118ec6fc672b291e49fc15a6d32c1e681f6b130e592, and Java/javac must match their independent executable pins. Inputs have exact official URL/size/SHA1/SHA256 locks: 133 SDK input objects plus the JDK ZIP and two official checksum/signature sidecars, 136 distinct initial objects. The sidecars are hash-checked; this adapter does not claim OpenPGP signature verification. The four vanilla SHA256 values are root's independent measurements of authenticated official bytes, not publisher-supplied SHA256 assertions; the freeze receipt digest is retained in the recipe. The original pending recipe remains only a pure negative-test fixture. No old SDK seeds any result.

Step 0 extracts server launch scripts/args and is deliberately omitted: they are unnecessary for these SDK parents and never executed. Client steps are 3,4,5,6,8,9; server steps are 1,2,3,4,5,7,8,9. Both step-4 DOWNLOAD_MOJMAPS executions remain real official processors. Copying the initially fetched mapping into their output is prohibited. Their actual output must match the frozen official mapping size/SHA1/SHA256 before merge. Server extraction expectations are derived from the authenticated official server JAR's embedded libraries/versions digest tables, never current output files.

Each JVM receives `-Xmx2G -XX:ActiveProcessorCount=2`, at most 900 seconds; all work has a 3600-second deadline and each workflow job 120 minutes. These are JVM options and controller deadlines, not an OS CPU/memory sandbox. Initial free disk must be at least 12 GiB, with a 2 GiB ongoing reserve. Both streams are drained incrementally under one synchronized, sticky 8 MiB combined process log cap; their individual digests remain separate. Local/global deadlines are checked before accepting exit0, after draining, around remaining verification IO and at final metadata serialization/write/rename. A late candidate is retained as unaccepted and the fixed upload filename records failure. A failure/timeout/reader error stops acceptance and does not retry. Only the owned Popen kernel handle is terminated when necessary.

Ordinary hosted network access is permitted. Initial GETs are exact locked URLs, with no proxy, auth, cookie, automatic redirect, fallback mirror, retry or TLS bypass. Only the official JDK GitHub release may redirect once to its fixed release-assets repository. Original library endpoints are retained; local TLS failures are historical facts, not authorization for an unreviewed mirror. Processor request observations are limited to bounded log URL digests; this is **not exhaustive packet/HTTP capture** and proves neither network denial nor absence of unlogged requests. Review unexpected observations; do not silently expand locks or claim an OS isolation property. No custom firewall, TLS broker, account or CA is part of this recipe.

Only the fixed `result.metadata.json` is uploaded. It contains input transport statuses/digests, process exit/log sizes and hashes, and full output ZIP entry name/CRC/size/SHA256 diagnostics. It contains no raw process text, class bytes, JARs, mappings, native files or patch bodies. Failure messages exported to CI are fixed categories. Compare both downloaded metadata receipts with `compare_runs.py recipe.json fresh-a.json fresh-b.json`; seven raw byte hashes must match the unchanged reference in both independent jobs. The comparison does not independently attest GitHub provenance: root must also verify both actual workflow jobs/artifacts. `reproductionAccepted` stays false until that review. No runtime QA, complete modpack rights or production readiness follows from SDK parent equality.

Pure checks: `python -B -X utf8 -m unittest -v test_hosted_sdk test_worker test_compare test_budget_repairs`. The path-only PowerShell function also has a real pure functional test: `./test_bootstrap_paths.ps1 -SourcePath ./bootstrap_paths.ps1 -FixtureRoot <new-own-fixture-directory>`; it exercises ordinary, junction and dangling-junction ancestors without launching Python or any vendor code. They use only own synthetic bytes and fake Popen; they do not download or run Java. `source-pins.json` locks reviewed Python and recipe files; the fixed bootstrap seals that table's SHA and the active recipe SHA, while the approved Git commit binds the bootstrap/workflow themselves. A changed source, recipe or bootstrap requires a newly reviewed commit, never runtime learning.
