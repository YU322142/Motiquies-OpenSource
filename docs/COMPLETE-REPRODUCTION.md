# 全部定制修改的公开复现验收标准

最终目标是：维护者从本仓库的固定提交、明确的合法上游输入和自己的运行数据，能够重建服务器的全部定制行为。发布若干修复模组只是其中一部分。当前完整覆盖尚未完成，组件登记中的 `serverReproductionComplete` 必须保持 `false`。

## 覆盖范围

| 类别 | 需要交付的复现材料 |
| --- | --- |
| 自有修复与联动模组 | 完整原创源码、原作者声明、固定编译输入、构建入口和运行验证 |
| 上游模组修改 | 精确上游版本与内容指纹、合法获取位置、获准公开的源码差异或独立补丁工具、修改后产物对比 |
| 配置与启动参数 | 无密钥的配置模板、默认值与覆盖顺序、必要参数及适用版本；实际地址与凭据由操作员提供 |
| KubeJS、配方、数据包与资源包 | 自有脚本和规则、加载顺序、依赖、资源来源与分发权；不能只记录模组文件 |
| 资源裁剪与兼容加工 | 固定原始输入、可审查处理程序、精确保留/删除范围、预期输出条目；禁止以不透明成品替代过程 |
| 世界版本转换与存量兼容 | 转换代码、适用输入版本、标识符及状态映射、保护与回滚步骤、无真实玩家信息的合成验收样例 |
| 客户端定制 | 多线路身份与共用数据、首次安装及升级迁移、个人数据选择与保护、地图下载控制和联动修复源码 |
| 地图、DH与配套服务 | 生成和同步程序、参数、调度与限额、变更追平、校验与恢复过程；内容使用操作者自己的世界生成 |
| 打包与维护 | 明确的客户端/服务端角色、锁定组件与许可清单、生成包的过程、隔离验收与可回滚部署说明 |
| 历史分支 | 与当前目标分开登记旧版本来源和适用范围，保留必要历史与迁移依据，不能当成当前生产版本 |

未改的第三方依赖可以只登记精确版本、合法来源和内容指纹；不要求复制整个上游项目。前提是已经核实其内容确实对应该发布版本，不能凭文件名推定未修改。

## 每项修改的闭环

1. **来源**：指出原始来源、准确版本或提交、输入文件指纹，以及实际修改的程序或源码。找不到的 producer 保持缺失状态，不能用相似代码或旧报告冒充原件。
2. **权利**：区分自有代码、第三方代码和资源。保留各自许可证与署名，处理 copyleft 的对应源码义务；不把根目录 MIT 扩展到第三方内容。无法确认的代码、素材与派生重建配方先不公开，也不能标成权利已闭合。
3. **输入可获取**：第三方应能按文档合法获取需要的依赖和工具。只有维护者电脑上存在的定制 SDK，或无法获得的私有底座，仍是复现缺口。
4. **独立构建**：使用固定工具链，在两个新输出目录构建，记录依赖校验、命令、退出状态与产物指纹。错误输入必须拒绝；不修改依赖来凑通过。
5. **输出对照**：与明确指定的参考版本比较 class、资源和条目集合。整包字节一致、条目内容一致、仅运行类一致是不同结论，差异必须解释。
6. **行为验收**：在隔离环境验证对应功能与回归。源码检查通过不能替代游戏内验收；当前生产、候选和历史工具分别记录。
7. **维护与部署**：公开改动与规范源码建立可追踪映射，固定发布提交并记录实际部署版本。公开合并或 CI 通过不会自动改生产。

这些条件全部满足后，才能把该项列为完整复现；所有范围逐项闭合后，才能改变整个项目的完整覆盖状态。公开 CI 的文本、指纹和输出边界检查只负责它们明确覆盖的内容，不构成授权、全服构建或游戏验收的自动证明。

## 数据与授权边界

复现定制逻辑不需要公开世界、备份、玩家 NBT、路标、JEI 记录、账号、令牌、真实网络拓扑或完整生产库存。配置中的私人值使用明示占位符，测试使用合成数据。测试个人数据保护时验证原数据未被意外改变，不把这些数据打入源码仓库或整合包。

对于受限上游，能够审查并单独公开的原创工具，应明确它只覆盖自己的代码。使用者自行提供原件不自动解决其他代码、素材、派生内容或二进制的分发授权。若确实无法获得所需权利，完整公开复现目标仍有缺口；替代实现或改变玩法需要单独说明，不能悄悄删功能来宣称完成。

Nostalgia 修改版及其重建配方目前没有分发授权，因此不公开；这项缺口不会被其他组件的开放许可抵消。当前其他已知不足继续登记在[缺口清单](REPRODUCTION-GAPS.md)。

## 重复仓库的处理

只有在功能与来源确实已覆盖、全部 Git 引用和发布物已经保全、外部链接与仍有用的历史内容已经核对后，才将旧仓库归档并指向新入口。仅名称相似、版本相同或源码大体重复不足以判定可清理。

仍有唯一行为、未闭合构建或权限问题的仓库继续保留。归档时保留原发布下载地址与历史；删除是另一个需要独立判断的动作，不是本次归档的默认步骤。全部迁移源码与必要回滚材料保留。
